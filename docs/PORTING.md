# Porting plan

msec ports the analysis core of MobSF v4.5.3 to Rust. The detailed inventory of what exists
upstream (modules, rules, data files, report keys, network calls, quirks) is in
[mobsf-inventory.md](mobsf-inventory.md).

## Principles

1. **Faithful by default.** Same checks, same rule data, same report keys. Each module names the
   upstream file it ports.
2. **Clear upstream bugs are fixed, never silently.** Every deviation is listed below with a test.
3. **Offline by default.** Every upstream network call (App Links, Play Store, App Store, Firebase
   probes, tracker and Maltrail refreshes, DNS) becomes an explicit opt-in. Database refreshes are
   maintenance calls, never side effects of a scan, so scans are deterministic.
4. **No mutation of inputs.** Upstream renames files and rewrites plists during IPA analysis; msec
   reads only.
5. **External tools stay optional.** jadx (with a Java runtime) is needed for code rules on APKs,
   as upstream. Everything else MobSF shells out to (apktool, aapt2, baksmali, apksigner,
   class-dump, `strings`, `nm`, `objdump`) is replaced natively.
6. **Golden diffs.** Upstream MobSF v4.5.3 (Docker image, outside this repository) runs on a fixed
   corpus; its JSON reports are compared section by section with msec output.

## Upstream deviations

| # | Upstream behaviour | msec behaviour |
|---|---|---|
| 1 | Extracts packages to disk with Python's `zipfile` | Never extracts: entries are read by name into memory, so entry names cannot write anywhere (`msec::archive`) |
| 2 | No limits beyond the upload size | Archive size, entry count, central directory size, per-entry output, total output and compression ratio are bounded ([`Limits`](../src/archive/limits.rs)); declared sizes are never trusted |
| 3 | Duplicate entry names: the last one wins (`zipfile`) | The first one wins, as on Android, and `DuplicateName` is reported |
| 4 | Structural tricks pass silently (prepended data, fake encryption flag, local header mismatches, overlapping entries, hidden data, second end record in the comment) | Each is reported as an `Anomaly`, marked when Android itself rejects it; the package is still analysed |
| 5 | CRC and size of extracted data are checked by `zipfile` and fail the extraction | A mismatch is reported as an anomaly and the data is still returned for analysis |
| 6 | Manifest attributes are read from androguard's decoded XML | `android:` attributes are matched by resource ID, as Android's package parser does; an attribute whose name string disagrees with its ID, or that has no ID, is reported (`XmlAnomalyKind::AttributeNameMismatch`, `UnresolvedAndroidAttribute`) and read the way Android reads it |
| 7 | Malformed binary XML handling follows androguard | Follows AOSP `ResXMLTree`/`ResXMLParser`: last string pool wins, nodes need a 16-byte header, a bad attribute block ends the document; each case is reported, marked when Android rejects it |
| 9 | Exported components protected by a framework permission (for example `BIND_JOB_SERVICE`) are reported as "protection level not defined", because only the app's own `<permission>`s are looked up | Framework permissions are looked up in the AOSP table too; signature-level ones count as protected (info), like the app's own |
| 10 | The launcher activity is excluded from exported findings only when the manifest names it fully qualified (`.Main` is compared with `com.app.Main`) | The launcher activity is always excluded |
| 11 | `minSdkVersion`/`targetSdkVersion` missing: platform checks are skipped, and StrandHogg checks assume target 26 | Android's defaults apply (minimum 1, target equal to minimum), so an app without `<uses-sdk>` is reported as installable everywhere |
| 12 | Every `<data android:port>` is reported as a data SMS port, including ports on web links | Only ports in filters for `DATA_SMS_RECEIVED` or with the `sms` scheme |
| 13 | `<data>` elements anywhere, including `<queries>`, feed the dialer-code and SMS checks; `<action android:priority>` is checked | Only components' intent filters (queries are not entry points); actions have no priority attribute in Android, so that check is dropped |
| 14 | App Links: `assetlinks.json` is fetched during every scan | Offline by default; the network check is deferred to an explicit online mode. Offline, http(s) links without `autoVerify` are reported (`msec_unverified_app_links`) |
| 15 | Network security config: the file is looked up in apktool output, with a fallback to any `*network_security*.xml` | Only the file the manifest references, as Android does; `@raw/` sources are named through the resource table; nested `<domain-config>`s are read with inherited cleartext; an expired `pin-set` is reported (`PinsExpired`) |
| 16 | Not checked | Added (msec origin): cleartext allowed by default (target below API 28, nothing set), user CAs trusted by default (target below API 24, no configuration) |
| 17 | Signature schemes are read from `apksigner` output (Java required) or androguard; signatures are not verified by MobSF itself | msec parses the APK Signing Block and JAR files and verifies everything: v2/v3/v3.1 signatures (RSA PKCS#1 and PSS, ECDSA P-256/384/521, DSA), chunked SHA-256/SHA-512 content digests, v1 PKCS#7 signatures (with or without signed attributes), `.SF` and manifest digests, unsigned entries. fs-verity digests are listed but not recomputed. v4 (`.idsig`) is a separate file |
| 18 | Janus: any v1 signature with a known minimum SDK is high; v1 with v2/v3 is a warning below Android 8.1 and high otherwise | v1 only: high when the app installs below Android 8.1; v1 with v2/v3: warning when it installs below Android 7.0 (the only releases that check v1 alone); nothing otherwise |
| 19 | Not checked | Added (msec origin): signatures that do not verify, Android releases in the app's range that would reject it (missing scheme, stripped v3, stripped v2 via `X-Android-APK-Signed`), RSA keys below 2048 bits, v1-only APKs targeting Android 11+, expired signer certificates (info) |
| 20 | Certificate details via asn1crypto (`get_cert_details`) | Same fields from `x509-cert`; the public key fingerprint is SHA-256 of the DER `SubjectPublicKeyInfo` (MobSF hashes a text rendering of the key numbers) |
| 21 | ELF parsed with LIEF; stripped-symbol check falls back to the host `nm` | In-house bounds-checked ELF parser (cross-checked against the `object` crate on 31 real NDK libraries); security properties from program headers and the dynamic segment, which is what Android's linker uses, so stripped or corrupted section headers do not hide them; dynamic symbols found through `DT_HASH`/`DT_GNU_HASH` when sections are missing |
| 22 | Full RELRO requires `DF_BIND_NOW` or `DF_1_NOW` | `DT_BIND_NOW` also counts (same meaning) |
| 23 | Dart detection also scans the binary's strings for the snapshot symbol names | Symbols only (dynamic and static) |
| 24 | Not checked | Added (msec origin): text relocations (Android 6.0+ refuses them), DWARF debug sections, 64-bit libraries aligned for 4 KB pages only (Google Play's 16 KB requirement), uncompressed libraries not page-aligned in the APK |
| 25 | Not checked | Added (msec origin): Google Play store readiness, `analysis::store_checks`. Target API level below Play's requirement for the app's form factor, from a dated table (2025 and 2026 requirements, extension window, existing-app threshold); `com.example` package names; `versionCode` missing, 0 or above 2100000000; 32-bit native code without 64-bit builds; permissions Play restricts to eligible core uses, which need a Play Console declaration but are not rejected for being requested (SMS and Call Log, QUERY_ALL_PACKAGES, All files access, REQUEST_INSTALL_PACKAGES, background location, exact alarms, full-screen intents, photo and video, Health Connect, accessibility and VPN services); foreground services for apps targeting API 34+: each declared type's permission, and services used without any type. `Component::foreground_service_type` was added to the manifest model for this |
| 26 | Classes are listed per DEX file by `baksmali list classes` (Java), for tracker matching only; DEX files are otherwise handed to jadx and APKiD | Native DEX reader (`msec::android::dex`), checked against AOSP's `dexdump` on d8 output in every version (035 to 041, including the 041 container format) and on hostile files. Added (msec origin): structural problems ART rejects (invalid strings, bad indexes, redefined classes, invalid map list, tables outside the file), checksum and SHA-1 signature mismatches, data after the end of the file, classes defined again in a later DEX file (Android loads the first), D8/R8 compiler markers. Hostile files that make strings or interface lists overlap are read within a budget of the file's size and reported as incomplete |
| 27 | `.aab`: `bundletool build-apks --mode=universal` (Java, 300 s timeout), then the APK pipeline on the universal APK | Read natively (`Bundle::read`), module by module: protobuf manifests and `res/xml` files (decoded by a bounded hand-written protobuf reader, checked line for line against `aapt2 dump xmltree` and against the binary manifests bundletool builds), `resources.pb` (giving the same IDs, names, values and locales as the `resources.arsc` built from the same sources), DEX files and native libraries, module kind and delivery, bundle problems. Feature modules' components and permissions are checked with the base module's SDK levels, findings keep their module path. The base module reads as an `Apk` holding every module's code and libraries, so every APK check runs. bundletool is not needed to scan; the fixtures are validated with it |
| 28 | Code rules are libsast regex patterns over JADX-decompiled sources (`android_apis.yaml` lists API usage such as `api_dexloading`); JADX and Java required | Not ported yet. Added instead (msec origin), on the DEX code itself with no decompiler: every reference each method's code makes, resolved through the app's and the framework's class hierarchy, and checks for deprecated and removed framework APIs (from `api-versions.xml`), Android 15 edge-to-edge APIs and handling, `BitmapFactory` without `Options`, wake locks acquired without a timeout, sign-in (calls into common sign-in SDKs) with no Restore Credentials or Block Store call for Google Play's zero-tap restoration requirement, and no sign of shrinking or obfuscation (no R8 marker, few renamed classes) where Google Play's DEX requirement applies. Each finding names the calling methods and whether each reads the Android version. A removed-API reference is reported as a reference, not a runtime failure (version checks, unreachable code and APIs the platform kept hidden all prevent one; reachability is not analysed), and the obfuscation estimate is a measurement, not Google Play's verdict |
| 29 | `.plist` files are read with Python's `plistlib` (and binary ones converted to XML in place), which keeps the last of duplicate keys in both formats and has no nesting limit | Read natively (`msec::plist`) with Core Foundation's rules, checked against `plutil`: the first duplicate wins in binary plists and the last in XML (as iOS reads them; recorded as `Anomaly::DuplicateKey`), 511 nested containers in XML and 513 levels in binary, no DTD processing, Core Foundation's number, date and base64 parsing. Objects shared in a binary plist are copied within a budget (`ExpansionBudgetExhausted`). OpenStep text and encodings other than UTF-8, UTF-16 and ISO-8859-1 are not read |
| 30 | IPA: the first `*.app` under a `Payload/` directory at any depth, extracted to disk | Read in place (`msec::ios::Ipa`): `Payload/<name>.app/` at the archive root, the first when there are several (`MultipleAppBundles`), else the shallowest `.app` anywhere (`AppBundleNotAtPayloadRoot`); `CFBundleExecutable` must be a plain file name the bundle has. Problems iOS's installer refuses are marked `rejected_by_ios`, each kind checked on the simulator |
| 31 | Mach-O read with LIEF; `MachOChecksec`: ARC when `_objc_release` or `_swift_release` is imported, stripped by `N_STAB` entries or objdump | Read natively (`msec::macho`). ARC also when clang's and swiftc's register-specific releases (`_objc_release_x20`, `_swift_release_x24`) or ARC-only entry points (`_objc_storeStrong`, `_objc_claimAutoreleasedReturnValue`, ...) are imported: today's toolchains no longer import the plain functions MobSF looks for. ld64's `N_OPT` marker (`radr://5614542`), present in every image, is not counted as debug information. Code signatures are parsed and their hashes verified (pages, Info.plist, CodeResources, requirements, entitlements), which MobSF does not do; CMS certificates are not read yet. `ios::analysis`: MobSF's checksec findings plus its IPA binary rules on imports, narrowed: the insecure-API rule keeps functions without a bounds argument (`gets`, `strcpy`, `strcat`, `sprintf`, ...; MobSF also lists `memcpy`, `strlen`, `malloc`, `printf`), and fortified calls (`__strcpy_chk`) are not flagged; binaries with Swift are not held to the stack protector (Swift code does not use it); rpaths in `/usr/lib/` and `/System/` are not "outside the bundle". Added: unsigned code, signatures that no longer match, rpaths outside the bundle, `get-task-allow` |
| 32 | ATS (`app_transport_security.py`): each `NSAppTransportSecurity` key reported on its own (`NSAllowsArbitraryLoads` high whatever else is set), exception domains' TLS 1.2 minimum graded as a warning, certificate transparency not required graded as a warning | Read with Apple's documented semantics (`ios::ats`): on iOS 10 and later `NSAllowsArbitraryLoads` is ignored when `NSAllowsArbitraryLoadsForMedia`, `...InWebContent` or `NSAllowsLocalNetworking` is present, so it is reported as in effect only when nothing overrides it or the app supports iOS 9 (`AtsArbitraryLoadsIgnored` otherwise, info); a TLS 1.2 minimum is ATS's default and not flagged; certificate transparency is read, not graded; the third-party and temporary key variants are read alongside the current ones; values of the wrong type are listed |
| 33 | Provisioning profiles: not read by MobSF's static analysis | Read natively (`ios::profile`, msec origin): the CMS signature (signer certificate's signature only; the chain to Apple is not checked) and content; checks for an unreadable or re-signed profile, expiry, a bundle identifier the profile does not provision, entitlements it does not allow (equal values, or a trailing `*` wildcard, per Apple's documentation; not verified on a device: the simulator's installer ignores profiles), and distribution outside the App Store. `msec::cms` replaces the JAR verifier's private PKCS#7 reader, adding BER (indefinite lengths, chunked octet strings) |
| 34 | `is_secret_key`'s "contains" list has `'certificate"'` with a stray quote, which no key can contain | `certificate` (the evident intent) |
| 35 | Secrets: string literals of jadx's decompiled sources, ELF strings, resource strings and plists; reported in full (`"key" : "value"`, `"<name>: <match>"`) | DEX strings read from the string table (every string that is not a type, member or source-file name: literals, static values, annotations), named by the class whose code loads them; native libraries' read-only sections; plus gitleaks' rules, text assets (`assets/`, `res/raw/`, bundle `root/`), the IPA's other text files and PKCS #12 file names (msec origin). Findings are classified (credential, client key such as a Google API key, possible secret) and the value is never kept: only a public prefix, the last four characters of credentials and client keys, and the length. gitleaks' recursive decoding (`--max-decode-depth`) is not ported yet |
| 36 | The key-name heuristic runs on every translation of a string resource, so a library's "Password" label is reported once per language | Runs on the default configuration's value (or the first when there is none); known formats still run on every translation |
| 37 | Trackers: the Exodus database refreshed from its API on every scan when online; IPA hosts reduced to their registrable domain with `tldextract` (Public Suffix List) before matching network signatures | A snapshot shipped with msec (`tools/generate_exodus_trackers.py`), never refreshed during a scan; network signatures matched against each URL's full host, so a signature written with a leading dot (`\.facebook\.com`) matches `graph.facebook.com` (it never matches a registrable domain) |
| 38 | SBOM: `*.version` files and the first `package` line of every decompiled source file, merged by prefix (`sbom_versioned`, `sbom_packages`) | `*.version` files read the same way; code packages from the DEX class descriptors, merged the same way, without the app's own package and names whose every part has one or two characters (obfuscated). Added (msec origin): the bundle's Gradle dependency record (exact coordinates, versions, SHA-256, graph, direct dependencies), `pom.properties`, Google Play services client files, native libraries and iOS frameworks, each component with its evidence and a confidence; the APK Signing Block's dependency record is noted, not read (it is encrypted for Google Play) |
| 8 | Permission protection levels come from MobSF's bundled table | Generated from AOSP's framework manifest (`tools/generate_android_data.py`), with Android's own user-facing labels |
